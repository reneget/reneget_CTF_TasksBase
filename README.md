# reneget_CTF_TasksBase

База авторских CTF-задач, разбитая по категориям. Репозиторий можно использовать как архив тасков, рабочую базу для доработки и удобную точку входа для новых людей, которым нужно быстро понять, как устроена конкретная задача.

На текущий момент все добавленные задачи относятся к соревнованию `NSK CTF 2026`.

## Как устроен репозиторий

Каждая задача лежит внутри своей категории:

```text
<category>/<task_name>/
```

Обычно задача оформляется примерно так:

```text
<category>/<task_name>/
├── README.md   # подробное описание задачи
├── public/     # файлы, которые выдаются участникам
├── deploy/     # опциональная инфраструктура для развёртывания
├── src/        # исходники, генераторы и авторские материалы
├── solve/      # writeup, exploit или пошаговое решение
└── ...         # дополнительные служебные файлы при необходимости
```

Не каждая задача обязана содержать все каталоги сразу:

- `public/` обычно нужен для файловых задач, где участникам выдаётся архив, дамп, изображение и т.д.
- `deploy/` нужен только там, где задачу надо поднимать как сервис.
- `src/` хранит исходники и внутренние материалы автора, если они есть.
- `solve/` содержит разбор, writeup или вспомогательные скрипты для решения.

## Что искать в README конкретной задачи

Обычно `README.md` внутри задачи содержит:

- легенду или краткое условие
- что именно нужно выдать участникам
- инструкцию по деплою, если задача сервисная
- краткое описание идеи задачи
- решение, writeup или ссылку на них
- флаг

Для сервисных задач участникам может выдаваться не папка `public/`, а только `IP:PORT` или домен. В таком случае детали запуска обычно лежат в `deploy/`, а внутренняя логика задачи находится в `src/`.

## Категории

В репозитории уже подготовлены следующие категории:

- `admin`
- `crypto`
- `forensic`
- `misc`
- `osint`
- `ppc`
- `pwn`
- `reverse`
- `stegano`
- `web`

Часть директорий пока пустая и зарезервирована под будущие задачи.
